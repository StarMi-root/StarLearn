# 计算机组成原理

代码最终会变成指令、内存访问和 I/O 操作。理解硬件组成，能解释“为什么这里快、那里慢”，也能避免把性能问题都归咎于语言或框架。

![计算机基础示意（开源图标：Simple Icons CC0 / Lucide ISC）](/static/img/icons/si-thealgorithms.svg)

## 抽象层次

```text
应用 → 算法与数据结构 → 编程语言/运行时 → 操作系统
     → 指令集架构 → 微架构 → 逻辑门 → 晶体管
```

每一层都向上提供抽象。高级语言不需要你手动管理寄存器，但理解底层仍能帮助排查性能、并发与内存问题。

## 五大部件

- **运算器**：算术与逻辑运算。
- **控制器**：取指、译码、控制执行。
- **存储器**：寄存器、缓存、内存、外存。
- **输入设备**：键盘、鼠标、传感器、网卡。
- **输出设备**：显示器、打印机、网卡。

现代 CPU 将运算器与控制器集成在核内，并通过缓存、内存控制器和 I/O 总线连接其他部件。

## 指令周期

```text
取指（Fetch）→ 译码（Decode）→ 执行（Execute）→ 访存（Memory）→ 写回（Writeback）
```

CPU 通过流水线让多条指令重叠执行。分支预测失败、缓存未命中、依赖链都会造成停顿。现代处理器还会乱序执行、 speculative execution，以提升指令级并行。

## 指令集架构

- **x86-64**：PC 与服务器主流，复杂指令集。
- **ARM64**：移动、Apple Silicon、云服务器，能效优秀。
- **RISC-V**：开放指令集，嵌入式与研究活跃。

源码通常需要针对目标架构编译。容器镜像也有架构区分：`linux/amd64` 与 `linux/arm64`。

## 存储层次

```text
寄存器    最快、最小、最贵
L1/L2/L3 缓存
主存 DRAM
SSD / HDD
网络存储
```

越靠近 CPU 越快但容量越小。性能优化常做的是**提高缓存命中率、减少内存访问、保持数据局部性**。

```c
// 行优先访问更符合数组内存布局，缓存更友好
for (int i = 0; i < n; i++) {
    for (int j = 0; j < m; j++) {
        sum += a[i][j];
    }
}
```

## 总线与 I/O

CPU 通过内存总线、PCIe 等连接设备。磁盘、网卡、GPU 常使用 DMA 直接访问内存，减少 CPU 搬运开销。

I/O 模型：

- 阻塞 I/O：调用后等待。
- 非阻塞 I/O：立即返回，轮询或事件通知。
- I/O 多路复用：`select`、`poll`、`epoll`、`kqueue`。
- 异步 I/O：提交后由内核通知完成。

高并发服务器的性能很大程度取决于 I/O 模型与内存拷贝次数。

## 性能指标

- **主频**：时钟周期频率，不等于实际性能。
- **IPC**：每周期执行的指令数。
- **缓存命中率**：L1/L2/L3 命中情况。
- **内存带宽**：单位时间可传输的数据量。
- **延迟**：一次操作从开始到完成的时间。
- **吞吐**：单位时间完成的工作量。

```text
程序时间 ≈ 指令数 × CPI × 时钟周期
```

减少指令数（算法）、降低 CPI（缓存/分支）、提高频率或并行度，都是优化方向。

## 二进制与数据表示

```text
1 byte = 8 bits
1 KiB = 1024 bytes
1 MiB = 1024 KiB
1 GiB = 1024 MiB
```

负整数常用补码表示。浮点数遵循 IEEE 754，存在精度问题：

```python
0.1 + 0.2 == 0.3  # False
```

金额用整数分或 `decimal`，不要用二进制浮点直接比较。

## 端序与对齐

- 大端：高位字节在前。
- 小端：低位字节在前，x86/ARM 常见。

结构体对齐会插入填充字节，影响内存占用与跨平台二进制协议。网络协议通常规定网络字节序（大端）。

## 从硬件看软件

- 数组遍历比链表更缓存友好。
- 频繁小对象分配增加分配器与缓存压力。
- 线程过多导致上下文切换与缓存抖动。
- GPU 适合大规模并行，不适合复杂分支。
- 数据库的随机 I/O 往往比顺序 I/O 慢得多。

:::tip 性能排查顺序
先测量，再优化。用 profiler 找热点，区分 CPU、内存、I/O、锁竞争和网络延迟。不要凭直觉重写代码。
:::

## 小练习

1. 用 `lscpu`、`free -h`、`lsblk` 描述你的机器配置。
2. 写一个行优先与列优先遍历的对比程序，观察耗时差异。
3. 解释为什么 0.1 + 0.2 不等于 0.3。
