# 正则表达式速查

正则表达式用于匹配、提取和替换文本。它强大但容易写错，尤其是边界、转义和回溯性能。

![正则表达式插画（开源图标：Simple Icons CC0 / Lucide ISC）](/static/img/icons/lu-regex.svg)

## 基础字符

| 模式 | 含义 |
|---|---|
| `.` | 任意字符（默认不含换行） |
| `\d` | 数字 |
| `\D` | 非数字 |
| `\w` | 字母、数字、下划线 |
| `\W` | 非单词字符 |
| `\s` | 空白 |
| `\S` | 非空白 |
| `[abc]` | a、b 或 c |
| `[^abc]` | 除 a、b、c |
| `[a-z]` | 小写字母范围 |

## 锚点与边界

| 模式 | 含义 |
|---|---|
| `^` | 行/字符串开头 |
| `$` | 行/字符串结尾 |
| `\b` | 单词边界 |
| `\B` | 非单词边界 |

多行模式下 `^`/`$` 匹配每行首尾，取决于语言与标志。

## 量词

| 模式 | 含义 |
|---|---|
| `*` | 0 次或多次 |
| `+` | 1 次或多次 |
| `?` | 0 或 1 次 |
| `{3}` | 恰好 3 次 |
| `{2,5}` | 2 到 5 次 |
| `{2,}` | 至少 2 次 |
| `*?` | 懒惰匹配 |
| `+?` | 懒惰匹配至少一次 |

默认贪婪：尽可能多匹配。加 `?` 变懒惰：尽可能少匹配。

## 分组与引用

```regex
(\d{4})-(\d{2})-(\d{2})
```

- `(...)` 捕获分组。
- `(?:...)` 非捕获分组。
- `(?<year>\d{4})` 命名分组。
- `\1` 反向引用第一个分组。
- `$1` 或 `\1` 在替换中使用，语法因工具而异。

## 选择与断言

```regex
cat|dog
(?=pattern)     正向先行断言
(?!pattern)     负向先行断言
(?<=pattern)    正向后行断言
(?<!pattern)    负向后行断言
```

示例：匹配后面不是 `.` 的单词：

```regex
\b\w+\b(?!\.)
```

后行断言在部分语言/版本中不支持或要求固定长度，使用前查文档。

## 标志

- `i`：忽略大小写。
- `m`：多行，`^`/`$` 匹配行首尾。
- `s`：点号匹配换行。
- `g`：全局匹配（JavaScript）。
- `u`：Unicode（JavaScript）。

Python 使用 `re.IGNORECASE`、`re.MULTILINE`、`re.DOTALL`。

## 常用示例

### 日期 YYYY-MM-DD

```regex
^\d{4}-(0[1-9]|1[0-2])-(0[1-9]|[12]\d|3[01])$
```

这只能校验格式，不能校验 2 月 30 日这类非法日期。日期合法性用日期库。

### 中国大陆手机号

```regex
^1[3-9]\d{9}$
```

规则会随号段变化，实际业务应结合运营商数据与产品要求。

### 邮箱（简化）

```regex
^[^\s@]+@[^\s@]+\.[^\s@]+$
```

完整 RFC 邮箱正则非常复杂。正确做法是：前端简单校验，后端发送验证邮件。

### IPv4（简化）

```regex
^(?:\d{1,3}\.){3}\d{1,3}$
```

仍需检查每段 0–255。网络地址使用专用库解析。

### URL 路径

```regex
^/api/(?<resource>[a-z]+)/(?<id>\d+)$
```

命名分组提高可读性，提取后仍需校验资源与权限。

## 贪婪与懒惰

```text
输入：<h1>标题</h1>
贪婪：<.*>      匹配整段
懒惰：<.*?>     匹配 <h1>
```

不要在 HTML 上用正则做完整解析。HTML 不是正则语言，使用解析器更可靠。

## 替换

JavaScript：

```javascript
const result = text.replace(/(\d{4})-(\d{2})-(\d{2})/g, "$1/$2/$3");
```

Python：

```python
import re
result = re.sub(r"(\d{4})-(\d{2})-(\d{2})", r"\1/\2/\3", text)
```

Shell `sed`：

```bash
sed -E 's/([0-9]{4})-([0-9]{2})-([0-9]{2})/\1\/\2\/\3/g'
```

不同工具的转义与替换语法有差异，先在小样本测试。

## 语言差异

| 特性 | JavaScript | Python | PCRE | Go RE2 |
|---|---|---|---|---|
| 后行断言 | 支持 | 支持（固定宽度） | 支持 | 不支持 |
| 命名分组 | `(?<name>)` | `(?P<name>)` | 两者 | `(?P<name>)` |
| 回溯 | 有 | 有 | 有 | 无（线性时间） |
| 全局标志 | `/g` | `findall` | 视工具 | 视工具 |

Go 的 RE2 引擎避免灾难性回溯，但不支持某些高级断言。选择引擎时要考虑安全与功能。

## 性能与安全

灾难性回溯示例：

```regex
^(a+)+$
```

输入大量 `a` 后跟 `!` 可能导致指数级尝试，形成 ReDoS。防护：

- 避免嵌套量词。
- 限制输入长度。
- 使用超时或线性时间引擎（RE2）。
- 对用户输入做预校验。
- 不在高并发路径使用复杂正则。

:::warn 不要用正则解析一切
HTML、JSON、SQL、邮箱和日期都有专用解析器。正则适合模式提取与简单校验，不适合完整语法分析。
:::

## 调试工具

- regex101.com：可视化分组与回溯。
- regexper.com：正则铁路图。
- 语言内置单元测试：把边界样本写成测试用例。

测试样本至少包括：正常、空字符串、超长输入、特殊字符、国际化字符、非法边界。
