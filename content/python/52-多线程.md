## 52.1 GIL（全局解释器锁）

CPython 的 GIL 让同一时刻只有一个线程执行 Python 字节码。

- **I/O 密集**：线程切换释放 GIL，多线程有效
- **CPU 密集**：多线程无收益（甚至更慢）

## 52.2 基本用法

```python
import threading

def worker(name):
    print(f"{name} running")

t = threading.Thread(target=worker, args=("A",))
t.start()
t.join()
```

## 52.3 线程池

```python
from concurrent.futures import ThreadPoolExecutor

def fetch(url):
    ...

with ThreadPoolExecutor(max_workers=8) as pool:
    futures = [pool.submit(fetch, url) for url in urls]
    for f in futures:
        f.result()
```

## 52.4 锁

```python
import threading

counter = 0
lock = threading.Lock()

def increment():
    global counter
    for _ in range(100000):
        with lock:
            counter += 1

threads = [threading.Thread(target=increment) for _ in range(4)]
for t in threads: t.start()
for t in threads: t.join()

print(counter)  # 400000
```

## 52.5 RLock 与条件变量

```python
rlock = threading.RLock()  # 可重入锁

cond = threading.Condition()
with cond:
    cond.wait()    # 等待
    cond.notify()  # 通知
```

## 52.6 信号量

```python
sem = threading.Semaphore(3)  # 最多 3 个线程
with sem:
    do_work()
```

## 52.7 线程局部存储

```python
local = threading.local()
local.value = 42
# 每个线程独立的 local.value
```

## 52.8 守护线程

```python
t = threading.Thread(target=daemon_work, daemon=True)
t.start()
# 主线程退出时自动终止
```

## 52.10 陷阱

```python
# 死锁
lock_a.acquire()
lock_b.acquire()  # 另一线程反之 → 死锁

# 修复：固定加锁顺序
```

## 52.11 何时用

- I/O 密集
- 简单并发
- 避免复杂共享状态

## 52.12 与多进程对比

| 场景 | 推荐 |
|------|------|
| I/O 密集 | 线程 |
| CPU 密集 | 多进程 |
| 突破 GIL | 多进程 |

## 小结

- GIL 限制 CPU 密集
- I/O 密集多线程有效
- 锁保护共享状态
- 线程池简化
