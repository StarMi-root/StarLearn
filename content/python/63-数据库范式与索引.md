# 第 13 章 数据库

# 63. 数据库范式与索引

## 学习目标

- 理解数据库范式
- 掌握索引作用
- 学会基本优化

## 63.1 为什么需要范式

- 减少冗余
- 避免更新异常
- 保持数据一致性

## 63.2 第一范式（1NF）

- 列原子（不可再分）
- 每行唯一

```sql
-- 违反
CREATE TABLE users (
    id INT,
    phones TEXT  -- "123,456,789"
);

-- 符合
CREATE TABLE phones (
    user_id INT,
    phone TEXT
);
```

## 63.3 第二范式（2NF）

- 满足 1NF
- 无部分依赖（候选键决定非键列）

## 63.4 第三范式（3NF）

- 满足 2NF
- 无传递依赖

```sql
-- 违反
CREATE TABLE orders (
    id INT,
    customer_id INT,
    customer_email TEXT  -- 传递依赖
);

-- 符合
CREATE TABLE customers (
    id INT PRIMARY KEY,
    email TEXT
);
CREATE TABLE orders (
    id INT,
    customer_id INT
);
```

复杂场景才需要。

## 63.6 反范式

有时为了性能故意冗余：

```sql
CREATE TABLE product_view (
    product_id INT,
    category_name TEXT  -- 冗余存储
);
```

权衡：读写性能 vs 一致性。

## 63.7 索引

```sql
CREATE INDEX idx_users_email ON users(email);
CREATE UNIQUE INDEX idx_users_email_uq ON users(email);
```

## 63.8 索引作用

- 加速查询
- 加速排序
- 唯一约束

## 63.9 索引代价

- 写入变慢
- 存储占用
- 太多索引影响优化器

## 63.10 常见索引类型

| 类型 | 场景 |
|------|------|
| B-Tree | 通用（=, <, >, BETWEEN） |
| Hash | 等值查询 |
| GIN | 全文搜索、数组 |
| GiST | 几何、JSONB |

## 63.11 EXPLAIN 分析

```sql
EXPLAIN ANALYZE SELECT * FROM users WHERE email = 'a@b.com';
```

查看是否用索引、扫描行数。

## 63.12 查询优化

- 避免 `SELECT *`
- 覆盖索引
- 避免函数包裹列
- 分页用 `LIMIT/OFFSET` 或游标

## 63.13 连接优化

- 小表驱动大表
- 索引匹配
- 避免笛卡尔积

## 63.14 统计信息

```sql
ANALYZE table_name;  -- 更新统计信息
```

## 63.15 事务隔离级别

```
READ UNCOMMITTED
READ COMMITTED
REPEATABLE READ
SERIALIZABLE
```

PostgreSQL 默认 READ COMMITTED。

## 63.16 常见陷阱

- 索引过多
- 全表扫描
- N+1 查询
- 锁冲突

## 63.17 性能监控

- 慢查询日志
- 执行计划
- 连接池统计

## 小结

- 范式减少冗余
- 索引加速查询
- EXPLAIN 优化
- 反范式权衡
