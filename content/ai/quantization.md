# GGUF 模型量化与显存估算

量化把模型权重从高精度浮点数压缩成更低比特表示，用更少的内存运行更大的模型。它不是无损压缩，需要在质量、速度和占用之间取舍。

## 为什么要量化

以 7B 参数模型为例：

| 精度 | 每参数大致字节 | 权重占用 |
|---|---|---|
| FP16 | 2 | 约 14 GB |
| Q8_0 | ~1 | 约 7–8 GB |
| Q5_K_M | ~0.7 | 约 5 GB |
| Q4_K_M | ~0.55 | 约 4 GB |
| Q2_K | ~0.3 | 约 2.5 GB |

实际占用还包括 KV Cache、计算缓冲和运行时开销。显存刚好等于权重体积时，通常会 OOM。

## 常见量化等级

- **Q8_0**：质量接近原始模型，体积较大。
- **Q6_K**：高质量，适合内存充足。
- **Q5_K_M**：质量与体积的较好平衡。
- **Q4_K_M**：最常用的默认选择，适合大多数 7B–14B 模型。
- **Q3_K_M**：内存紧张时的折中，质量下降明显。
- **Q2_K**：只适合极端受限环境，不推荐用于严肃任务。

“K”表示使用 k-quants 分块量化，“M”通常表示中等混合精度策略。不同模型、不同任务对量化的敏感度不同，不能只看名字。

## 显存估算

粗略公式：

```text
总占用 ≈ 权重 + KV Cache + 计算缓冲 + 框架开销
KV Cache ≈ 层数 × 上下文长度 × 隐藏维度 × 2 × 精度字节 × 批大小
```

实际估算建议：

1. 先看模型仓库给出的量化文件大小。
2. 预留 15%–30% 余量给上下文和运行时。
3. 上下文从 2048/4096 开始，逐步增加。
4. 用 `nvidia-smi` 或 `llama-bench` 观察真实占用。

例如 Q4_K_M 的 7B 模型约 4.5 GB，在 8 GB 显存上可以运行 4K–8K 上下文；在 6 GB 显存上可能需要减少上下文或卸载部分层到 CPU。

## 使用 llama-quantize

先准备 FP16 GGUF 模型：

```bash
./build/bin/llama-quantize \
  models/model-f16.gguf \
  models/model-Q4_K_M.gguf \
  Q4_K_M
```

查看支持的量化类型：

```bash
./build/bin/llama-quantize --help
```

常见类型：`Q4_0`、`Q4_K_M`、`Q5_K_M`、`Q6_K`、`Q8_0`。优先选择带 K 的版本，通常质量更好。

## 重要性矩阵

高级量化会使用重要性矩阵（imatrix）来减少敏感层的损失：

```bash
# 先用校准文本生成 imatrix
./build/bin/llama-imatrix \
  -m models/model-f16.gguf \
  -f calibration.txt \
  -o models/model.imatrix

# 再量化
./build/bin/llama-quantize \
  --imatrix models/model.imatrix \
  models/model-f16.gguf \
  models/model-Q4_K_M.gguf \
  Q4_K_M
```

校准文本应接近目标使用场景。用代码语料校准代码模型，效果通常比通用文本更好。

## 质量评估

不要只看困惑度（perplexity）。建立自己的小评测集：

- 20–50 个真实问题；
- 覆盖事实、推理、代码、格式遵循；
- 记录正确率、延迟、显存；
- 对比 Q4_K_M、Q5_K_M、Q8_0。

```text
模型：7B
量化：Q4_K_M vs Q5_K_M
硬件：RTX 4060 Ti 16GB
上下文：4096
指标：正确率 / tokens/s / 峰值显存
```

如果 Q4 在你的任务上已经足够，Q5 的额外体积可能不值得。反之，代码生成和长链推理对量化更敏感，建议优先 Q5 或 Q6。

## 运行参数配合

```bash
./build/bin/llama-server \
  -m models/model-Q4_K_M.gguf \
  -c 8192 \
  -ngl 99 \
  --host 127.0.0.1 \
  --port 8080
```

- 显存不足：降低 `-c`、降低 `-ngl`、换更低量化。
- 速度慢：确认 GPU 卸载、检查是否内存交换、减少上下文。
- 质量差：提高量化等级、换更大模型、优化提示词。

## 量化不是万能药

- 小模型量化后仍然受参数容量限制，不能替代更大模型。
- 低比特量化可能破坏指令遵循和代码语法。
- 量化模型与原始模型的许可证仍需遵守。
- 生产环境应固定模型文件与校验和，避免悄悄换版本。

:::tip 实用建议
个人电脑优先从 Q4_K_M 开始；如果显存允许且任务对质量敏感，升级到 Q5_K_M。把“能跑”与“跑得好”分开评估。
:::

## 小练习

1. 下载同一模型的 Q4_K_M 与 Q5_K_M，比较生成速度与显存占用。
2. 用 20 个问题做小评测，记录两种量化的差异。
3. 把上下文从 2048 增加到 8192，观察显存与速度变化。
