# AI Agent 智能体：从聊天机器人到任务执行

聊天机器人只回答一句话，Agent 则要完成一件事：查资料、改代码、运行测试、根据结果继续行动。它的核心不是“更长的提示词”，而是一个可观察、可控制的任务循环。

## Agent 与普通对话的区别

| 维度 | 普通聊天 | Agent |
| --- | --- | --- |
| 目标 | 生成回答 | 完成多步任务 |
| 输入 | 当前问题 | 问题 + 环境状态 |
| 行动 | 只输出文本 | 调用工具、读写文件、执行命令 |
| 反馈 | 无 | 观察工具结果并调整计划 |
| 风险 | 说错话 | 误删文件、泄露数据、执行危险命令 |

一个 Agent 至少包含四部分：**模型、工具、记忆、循环控制**。模型负责推理和选择，工具负责真正做事，记忆保存上下文，循环控制决定何时停止。

## 最小 Agent 循环

```python
def run_agent(goal, tools, max_steps=8):
    history = []
    for step in range(max_steps):
        decision = model_decide(goal, history, tools)
        if decision.type == "final":
            return decision.answer
        result = tools[decision.tool].run(decision.arguments)
        history.append({
            "step": step,
            "tool": decision.tool,
            "arguments": decision.arguments,
            "result": result,
        })
    return "达到最大步数，任务未完成"
```

这个循环的关键点：

1. **最大步数**：防止无限调用和费用失控。
2. **工具白名单**：只能调用注册过的工具。
3. **参数校验**：执行前检查路径、命令和权限。
4. **结果观察**：把工具输出放回上下文，让模型决定下一步。
5. **终止条件**：模型可以主动结束，控制器也可以强制结束。

## 规划：先拆任务，再行动

复杂任务要先分解：

```text
目标：修复登录接口 500 错误
1. 查看错误日志，定位异常堆栈
2. 找到对应控制器和 service
3. 复现问题，写一个失败测试
4. 修改代码
5. 运行测试和静态检查
```

规划不等于一次性列出完美步骤。真实 Agent 会根据工具结果修订计划。工程上更可靠的做法是“计划 + 执行 + 校验”三阶段，而不是让模型自由发挥。

## 工具调用

工具是 Agent 与外部世界之间的边界。设计工具时遵守：

- **窄接口**：一个工具只做一件事，例如 `read_file(path)`，不要做 `do_everything()`。
- **强校验**：路径限制在工作目录，命令限制在白名单，网络请求限制域名。
- **可回滚**：写操作先备份或使用临时目录，危险操作要求人工确认。
- **结构化输出**：返回 JSON，包含成功标志、数据和错误信息。
- **幂等**：重复调用不会产生重复副作用。

```json
{
  "tool": "read_file",
  "arguments": { "path": "src/main.py" }
}
```

工具返回：

```json
{
  "ok": true,
  "content": "def main():\n    ...",
  "truncated": false
}
```

不要让模型直接拼接 shell 命令。应该使用参数数组和固定命令模板，避免命令注入。

## 记忆：短期与长期

- **短期记忆**：当前任务的对话、工具结果、错误信息。
- **长期记忆**：项目规范、用户偏好、历史决策，通常存入向量库或数据库。
- **工作记忆**：当前文件内容、测试结果等临时状态。

记忆不是越多越好。无关记忆会挤占上下文、增加成本，还可能引入过时信息。检索记忆时要带来源和时间，重要决策保留原文。

## 反思与评估

Agent 需要知道自己是否成功。最低要求：

1. 每个工具返回明确成功/失败。
2. 关键任务有自动化测试或校验脚本。
3. 失败时保留错误信息，不要假装完成。
4. 记录每一步的工具、参数、结果和耗时。
5. 用固定任务集评估成功率，而不是只看一两个演示。

```python
def verify(result):
    if not result["ok"]:
        return False, result["error"]
    tests = run_tests()
    return tests.returncode == 0, tests.stderr
```

## 安全边界

Agent 能执行代码，就必须按“不可信执行者”对待：

- 默认只读，写操作需要显式授权。
- 限制工作目录，阻止 `../` 路径穿越。
- 密钥放在环境变量或密钥管理服务，绝不进提示词。
- 对删除、支付、发布、发送邮件等不可逆操作要求人工确认。
- 记录审计日志，保留工具调用和文件变更。
- 对外部网页、邮件、文档中的指令保持警惕，防止提示词注入。

:::danger 不要直接放权
“让 Agent 自动修复生产服务器”不是学习项目的好起点。先在本地仓库、临时目录和可回滚环境里练习。
:::

## 常见架构

- **ReAct**：推理与行动交替，适合搜索、问答和工具编排。
- **Plan-and-Execute**：先规划再执行，适合步骤明确的任务。
- **多 Agent**：规划者、执行者、审查者分工，适合复杂工程，但成本和调试难度更高。
- **工作流 Agent**：把步骤固定为 DAG，只在关键节点调用模型，可靠性更高。

LangChain、LlamaIndex 等框架提供工具、记忆和编排抽象，但不要为了用框架而用框架。一个 50 行的循环加清晰工具，往往比复杂编排更容易维护。
