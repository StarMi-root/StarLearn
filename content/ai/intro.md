# 大模型基础：从 Token 到本地推理

学习 AI 应用开发，不需要先推导所有数学公式，但必须理解模型如何工作、能力边界在哪里，以及推理成本由什么决定。这一页建立后续 llama.cpp、RAG 与 Agent 学习所需的概念地图。

## 大模型在做什么

语言模型的核心任务是根据已有上下文预测下一个 Token。重复这个过程，就生成了完整回答。它并不是在数据库里检索一句话，而是根据训练得到的参数分布逐字生成。

```text
输入：C# 中用于异步等待的关键字是
模型：await
继续预测：，它会释放当前线程……
```

这解释了两个重要事实：

1. 模型输出是概率性的，同一个问题可能得到不同表述。
2. 模型可能“流畅地编造”，因为它优化的是像不像，而不是真不真。

## Token 与上下文

Token 是模型处理文本的基本单位。英文单词可能对应一个或多个 Token，中文通常按字或词片段切分。

- **上下文窗口**：模型一次能看到的 Token 总数，包括系统提示、历史对话、参考资料和输出。
- **上下文越长，成本越高**：注意力计算和显存占用都会增加。
- **超出窗口**：旧内容会被截断，模型会“忘记”前面的信息。

工程上要主动控制上下文：只放必要资料，摘要历史对话，不要把整站文档一次性塞进去。

## Transformer 直觉

Transformer 的关键是**注意力机制**：生成每个 Token 时，模型会关注上下文中相关的部分。多层注意力与前馈网络叠加，形成对语法、事实和推理模式的建模。

你不需要手写注意力公式，但应知道：

- 模型没有真正的长期记忆，记忆来自每次传入的上下文。
- 微调改变模型参数；RAG 改变输入资料；Agent 改变模型可调用的工具。
- 量化降低权重精度，用少量质量换更低的显存占用。

## 推理参数

| 参数 | 作用 | 建议 |
|---|---|---|
| `temperature` | 控制随机性 | 代码/事实 0–0.3；创意 0.7–1.0 |
| `top_p` | 核采样范围 | 通常 0.9–1.0 |
| `max_tokens` | 最大输出长度 | 按任务限制，避免无意义长文 |
| `repeat_penalty` | 抑制重复 | 轻微调整，过高会伤害表达 |
| `seed` | 随机种子 | 需要可复现时固定 |

参数不是越高越好。代码生成优先低温度；头脑风暴可以适当提高。

## 本地模型 vs 云端 API

| 维度 | 本地推理 | 云端 API |
|---|---|---|
| 隐私 | 数据不出本机 | 数据发送给服务商 |
| 成本 | 硬件一次性投入 | 按 Token 计费 |
| 延迟 | 取决于硬件 | 通常较低且稳定 |
| 模型规模 | 受显存/内存限制 | 可用超大模型 |
| 运维 | 需要自己升级、监控 | 服务商负责 |
| 适合 | 隐私数据、离线、学习 | 快速上线、弹性流量 |

常见本地推理方案：

- **llama.cpp**：C/C++ 实现，CPU/GPU 混合推理，GGUF 量化生态。
- **Ollama**：模型管理与运行封装，开箱即用。
- **vLLM**：面向高吞吐服务端推理，GPU 为主。
- **LM Studio**：桌面图形界面，适合体验。

## 硬件与模型规模

粗略估算显存需求：

```text
显存 ≈ 参数量 × 每参数字节数 + KV Cache + 运行时开销
```

以 7B 模型为例：

- FP16：约 14 GB 权重，通常需要 16 GB 以上显存。
- Q8_0：约 7–8 GB。
- Q4_K_M：约 4–5 GB，是常见折中。
- 上下文越长，KV Cache 越大；长上下文会显著增加占用。

CPU 推理可以运行，但速度取决于核心数、内存带宽和量化方式。GPU 卸载层数 `-ngl` 是 llama.cpp 的关键参数。

## 幻觉与验证

模型可能：

- 编造不存在的 API、论文、链接；
- 把相似概念混在一起；
- 给出能运行但逻辑错误的代码；
- 忽略你刚刚说过的约束。

应对方式：

1. 要求给出处，并自己核对。
2. 代码必须运行测试。
3. 用结构化输出与 schema 校验。
4. RAG 提供可信资料，并要求引用。
5. 高风险场景保留人工审核。

:::warn 重要认知
模型不是数据库，也不是编译器。它可以加速工作，但不能替代验证。把 AI 输出直接部署到生产环境，是工程上非常危险的做法。
:::

## 学习路线

1. **概念**：Token、上下文、采样参数、量化。
2. **本地运行**：编译 llama.cpp，下载 GGUF，启动 CLI 与 API。
3. **工程化**：量化选择、显存估算、并发与监控。
4. **增强**：Prompt、RAG、工具调用与 Agent。
5. **应用**：把模型接入网站、桌面应用或自动化流程。
